# 前端开发规则

适用于 `frontend/`，与根目录 [AGENTS.md](../AGENTS.md) 一起使用。

## 页面与组件

- `App.jsx` 管理首页、鉴权与用户隔离；`StudioView.jsx` 管理工作台导航与 Provider；`GenerateView.jsx` 编排调色项目。新增功能优先沉入组件、hook 或 `lib/`，避免继续扩大页面编排。
- 沿用 React 18、JavaScript/JSX、Vite 与普通 CSS。不要为局部功能引入整套框架、CSS 库或 TypeScript 迁移。
- 菜单、确认、对话框、提示、滑块和下拉选择优先复用 `components/ui/`、`SelectField.jsx` 与现有字段组件，保持 Radix 的键盘、焦点和关闭行为。
- 使用 `themes.css` 的语义变量；浅色保持清晰明亮，深色和中性灰也需可读。照片舞台和图表的中性背景不可被主题改变为新的像素处理。
- 常规布局检查 390px 窄屏与桌面；长名称、展开曲线、放大照片并调参、错误提示都不能遮挡主要操作。
- 给输入明确 label，给图标按钮可访问名称；Dialog 有标题与说明，关闭后恢复焦点。加载、空状态、失败、禁用及保存未完成需表达真实状态。

## 调色状态

- 参数、来源、创作目标和保护项通过 `hooks/useWorkspace.js` 与 `lib/workspace.js` 的事务更新。一次连续拖动或一次效果应用应能整体撤销，取消手势应恢复原状态。
- 不直接修改 workspace 对象或通过局部组件 state 维护第二份正式参数。候选预览和固定 A/B 快照不应改写草稿。
- 区分正在查看的样张与 AI 主样张；切换缩略图不等于更换 AI 输入。所有候选与恢复核对来源、输入、保护上下文及项目身份。
- 复制项目保持独立 ID 与会话，并按 `lib/projectManagement.js` 重置历史、报告和作业标记；保留样张元信息及已选择的预览缓存。
- 草稿、预览和作业回执按账号与项目隔离。保留修订冲突、删除标记、排队保存的身份检查；项目删除后旧标签页或迟到响应不能复活草稿。
- 原始 File 不随本机 JSON 草稿持久化。刷新后的缩小缓存不能当作完整分辨率原文件；导出前提示重新绑定。

## 色彩与参数

- 前端引擎与后端数学一致。字段变化同步默认值、控件、中文标签、说明、保护分组、API 及工具契约，不能只加一个滑块。
- 预览、缩略图、统计和导出使用统一的图片规范化及显示色彩路径；不要通过 CSS filter 模拟正式调色。
- 外部 LUT 与自由曲线走现有合成链路。避免技术转换被重复应用，输入待确认时不能展示具有误导性的正式比较。
- WebGL、Canvas、图片对象 URL 和事件订阅遵守已有生命周期清理。新异步请求需阻止过期响应覆盖当前项目或照片。

## 加载边界

- 保留 `FeatureLoader.jsx` 的动态导入、真实功能入口 URL 与重试方式；`?lazy-url` 由 `build/lazyModuleUrls.mjs` 处理。
- 首页不能静态引入完整工作台；工作台不能提前加载所有页面；曲线、参考图、照片导出与放大工具打开时再加载。
- 判断加载成本依据生产 manifest 的传递依赖，不能只看单个源文件或关闭 chunk 警告。

## 验证命令

以下命令在 `frontend/` 执行：

```bash
npm test
node --test scripts/test_project_management.mjs
npm run build
npm run check:loading
```

`check:loading` 必须在构建之后执行。测试使用 Node 内置 runner；部分用例还依赖已安装的 React/esbuild 或根目录 `.venv` 的 Python，不能声称是零依赖测试。当前没有 `lint` 或 `typecheck` npm 脚本，不写不存在的检查命令。

界面改动追加实际浏览器验收，包括适用主题、键盘、窄屏及状态转换。仓库没有提交的浏览器自动测试套件；记录所用浏览器流程和结果，测试账号与缓存清理只作用于本次验收数据。
