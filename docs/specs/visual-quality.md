# CHROMA 整体视觉质检与优化

## 目标

让落地页、登录页、生成工作台、放大查看、我的 LUT 和相关浮层拥有一致的视觉语言。浅色主题清晰明亮，照片是视觉中心；信息层级通过字号、留白和轻量边界表达。保持现有调色、预览、导出和作业行为。

## 当前问题

- 浅色次级背景偏灰，卡片、折叠标题和嵌套信息框同时使用强描边，页面显得厚重。
- 父容器间距与子模块外边距叠加，落地页纵向留白过大，库页面标题、筛选和卡片之间缺少稳定节奏。
- 参数组标题和操作按钮分成两行，折叠后占据过多空间；曲线区边界层级过多。
- 卡片内容长短不一造成操作栏错位，控件高度、文字大小与圆角档位过多。
- 落地页部分说明未覆盖当前能力，并含有不能保证的速度和兼容性表述。

## 视觉规则

### 主题与层次

- 浅色页面使用近白背景、白色主面与柔灰辅助面。主文字保持深灰，辅助文字保留可读对比。
- 分隔线使用 `--line`；输入边界使用 `--control-line`；滑块轨道等需要更强识别的元素继续使用 `--linestrong`。键盘焦点保持明确。
- 暖色仅用于主要动作、选中状态和小面积提示。普通说明使用中性面，警告使用语义色。
- 照片和曲线画布保持固定中性色，主题不改变照片像素、渲染颜色或色彩管理。
- 深色和中性灰沿用同样的层级与布局规则，避免浅色优化破坏其他主题。

### 排版与间距

- UI 字体以 Manrope、中文系统字体和系统无衬线字体组成一致栈；标题、正文和数字使用有限的大小档位。
- 工具页面外侧间距为桌面 24px、手机 16px；主要区块间距 20–24px，内部 16px，相关控件 8–12px。
- 落地页主要章节桌面 64px 左右、手机 40–48px；标题到内容 24–32px。避免外层 gap 和内部 margin 叠加。
- 普通操作控件以 40px 为基准，密集工具以 34–36px 为基准；触屏交互保留足够点击区域。
- 面板圆角以 12px 为主，控件 8px；照片保持适当边界，不使用多层装饰边框。

## 页面方案

### 落地页

- 导航、正文和页脚使用同一内容宽度，照片对比作为首屏主要视觉。
- 缩短章节和功能行的累计留白；说明示意按内容自然高度排版，照片保持比例。
- 移动端功能模块统一先说明后示意。流程编号不覆盖正文。
- 文案准确体现 AI 创作、手动微调、四通道曲线、参考图匹配、外部 LUT 试套和照片导出；示例明确标注，不承诺确定耗时或未经确认的兼容性。

### 生成与放大查看

- 参数组名称、展开入口和轻量操作在同一行，摘要按需要换行。
- 参数标题、帮助、数值和保护状态对齐；减少大块灰底和嵌套框。
- 曲线保留主、R、G、B 同时展示，通道面板弱化边界；画布与控制文字清晰。
- 放大查看侧栏保持足够调节宽度，预览与参数区层级清楚。

### 我的 LUT 与弹窗

- 标题、检索、结果信息和卡片以稳定间距连接。
- 卡片主体采用纵向布局，操作栏底部对齐；载入为主要动作，其余操作降低视觉权重。
- 手机筛选避免孤立控件；表单、选择器与按钮视觉高度一致。
- 弹窗外框使用弱线与克制阴影，内部信息使用柔灰面；保留 Radix 的焦点管理、键盘操作和危险动作确认。

## 验收

- 浏览器检查桌面与手机的落地页、登录页、工作台、曲线、放大查看、库页面和代表性浮层。
- 检查浅色、深色和中性灰主题；检查是否存在横向溢出、控件拥挤、文字低对比和重复边框。
- 使用现有主题对比度验证、前端回归测试与生产构建验证。
- 不调用收费 AI 作业，不修改用户调色数据；验证中产生的临时数据单独清理。
