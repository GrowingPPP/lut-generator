# AI 判断准确性与前端按需加载

日期：2026-10-12。

## 范围与问题

本轮处理实际样张验收中发现的三个 AI 质量问题，然后优化前端加载。真实照片艺术效果矩阵、真实模型风格接受度和相机导入／实拍验收继续待办。

| 问题 | 原因 | 预期结果 |
| --- | --- | --- |
| 树皮和暖色风景被当作肤色保护 | 颜色阈值命中直接成为人物证据 | 疑似肤色颜色统计与人物上下文分开，明确包含人物时才启用人物颜色漂移保护 |
| 前后效果相同，复核仍描述改善 | 复核没有有效变化门槛 | 相同效果跳过前后改善评价，报告明确未改变 |
| 空复核意见被标为完成 | 没有验证模型返回的有效文字 | 空响应有独立原因，复核阶段和报告准确显示未完成 |
| 公共落地页下载整个编辑器 | 入口静态导入页面和照片工具，并挂载隐藏工作区 | 页面与工具按使用时机加载，已打开工作区切页后保持状态 |

## 肤色证据与样张上下文

- `subject_mode` 为编辑上下文，取值为 `unknown`、`portrait`、`non_portrait`，不属于 LUT 调整参数。
- 界面以“照片内容：未确认／包含人物／无人物”表达。标注保存在对应样张的元数据；旧草稿缺省为未确认。切换主样张使用新主样张的标注，同一来源原文件重新绑定保留标注。
- 颜色掩码只证明像素颜色接近肤色，统计、提示与报告称“疑似肤色颜色区域”。系统不声称具有人脸检测或人物分割能力。
- 只有明确包含人物时启用已有颜色漂移保护，阈值保持。未知或无人物仍受裁切、饱和度增长、参数范围、曝光步长及参数保护等现有规则约束。
- 校正、风格、规则兜底、参考匹配和资产候选检查遵循同一证据规则。检查多张图片时，人物上下文按每张被检查的样张确定。
- 作业请求摘要、恢复比较和报告保留上下文；不同人物标注不能被当作同一个请求。历史记录和旧回执兼容缺省值。

## 视觉复核结果

- 最终候选与调整前效果没有可见变化时，跳过复核，不发送前后改善请求。需要覆盖参数未变以及参数虽变但渲染效果相同的情况。
- 明确区分有效复核、无变化、用户关闭、无客户端、无可执行阶段、调用失败与空内容。阶段状态不能把空内容标为有效完成。
- 有效意见去除首尾空白；空字符串、空白、缺少 choices、非字符串内容均不构成有效意见。
- 复核失败不丢弃已经通过校验的调色结果；已有模型用量仍如实记录。前端将原因转为用户可理解的文字。

## 前端加载与状态保持

- 以生产构建和浏览器脚本请求为度量。原入口 JavaScript 为 612,107 字节，gzip 约 202.78kB；公共落地页实际请求该完整文件。
- 工作区从入口组件提取，登录、资产库、工作区和照片工具使用动态模块边界。公共落地页不提前挂载工作区，也不请求工作区或会话数据。
- 工作区首次进入时挂载，此后导航切页只隐藏。登录身份变化释放旧工作区；参数、照片、撤销、曲线、参考候选及运行作业不因普通导航丢失。
- 自动修图控制器随工作区保持挂载；参考匹配和其他有本地状态的面板首次访问后保留。
- 放大调色与照片导出使用局部加载反馈。模块失败提供局部重试；失败的工具不能卸载整个工作区。重试需重新建立失败的 lazy 模块实例，避免复用被缓存的失败。
- 重试使用构建器提供的实际模块入口 URL，追加新请求标识；先等待已失败的样式重新加载成功，再挂载功能。成功恢复的模块可继续复用。版本更新或静态依赖持续失败仍保留“保存后刷新”的提示。
- 页面专用样式随页面加载；基础主题和控件风格保持统一。以实际首屏总下载量衡量改善，不以拆成多个仍同时加载的文件作为结果。

2. 实现样张标注、上下文验证、各候选检查和复核门槛；验证草稿、请求摘要与恢复兼容。

4. 运行相关回归及项目检查，在生产预览中验证首次加载、导航状态保持、照片工具和模块失败重试。
5. 独立代码复核、简化重复逻辑、更新验收记录和此前实际样张记录的修复状态。

软件回归采用确定性模型响应。该验证可以确认保护规则、调用门槛和状态真实性，不等同于真实模型的艺术效果验收。

## 本地服务契约同步

用户在实际 `localhost:5173` 触发样张验证时，`subject_mode=non_portrait` 被旧后端的 `ValidationSample` 作为额外字段拒绝。通过该地址的真实代理请求复现 HTTP 422；当前磁盘源码已经接受此字段，但监听 8000 的后端在代码更新前启动且没有自动重载，公开的 `EditingContext` 契约也仍缺少该字段。

处理方案：重启现有开发服务使其加载当前代码；开发启动命令监视服务源码目录并自动重载；补充样张清单经过 multipart HTTP 解析的三态、缺省值及非法值回归；从用户实际前端代理复验，保留严格的字段校验和每张样张的内容标注。

执行结果：已替换实际 8000 旧进程，以源码重载模式运行当前代码；使用 `_1026453.JPG` 经 `localhost:5173` 代理请求，无人物、包含人物、旧清单缺省均返回 HTTP 200，并分别回传正确的人物保护状态。新增 7 项 multipart HTTP 回归通过，包含同批混合四样张、报告持久化，以及六类非法值拒绝。开发启动的 PID 文件改为相对仓库根写入，记录实际重载进程，避免后台切换目录影响进程管理。
