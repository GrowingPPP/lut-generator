# 刷新后原照片重新绑定与恢复

## 问题依据

重启或刷新后，草稿只持久化照片元信息及可选缩小预览，原文件需要用户重新选择，这是现有数据边界。

浏览器使用真实生成页面、隔离的合成项目与规范化响应复现：延迟读取旧预览缓存，先完成同源原文件绑定，再释放缓存读取，页面从“已绑定，可用于照片分析及原尺寸导出”退回“仅有缩小预览，原文件需重新绑定”。旧恢复任务整体覆盖媒体 Map，丢失了新绑定 File。

文件选择还有两个相关缺口：选择器期间进入忙碌状态会静默忽略选择，且不清理文件输入；错误仅写到全局状态，照片入口附近缺少结果反馈。

## 方案

1. 缓存恢复只补充当前项目仍存在、来源与预览身份匹配的照片。核对缓存元信息与已记录的预览像素摘要；合并时优先使用最新媒体状态，不覆盖先完成的原文件绑定，不恢复已移除的样张。
2. 打开选择器时同步记录项目、账号、目标样张，文件回调冻结该意图，不依赖下一次 React 渲染才能确定目标。已有五张时仍可重绑，不能误走新增流程。
3. 读取选择结果后立即清空输入值与选择意图，取消或忙碌时也能再次选择同一文件。若项目已改变，放弃迟到选择；目标样张已移除则拒绝，不新增替代引用。
4. 照片区显示载入中、绑定成功与具体失败原因。忙碌时明确提示稍后重试；同源绑定保留输入确认，输入不匹配仍提示核对。
5. 保留原文件 SHA-256 校验、人物区域与输入契约。内容不同的文件不能替换旧引用；刷新后仍不能把缩小缓存当作原文件。
6. 所有异步解码与缓存完成均检查项目身份。失败保留原样张和已有预览，不让晚到响应改写其他项目。

## 验收

- 原文件先绑定、旧缓存后恢复：File 与最新预览保持可用。
- 无缓存与有缓存的刷新恢复，正常绑定、同文件重试和取消选择。
- 不同内容同名文件、规范化失败，入口显示原因且可选择正确原文件恢复。
- 五张样张时重绑只替换目标，数量、主样张、参数、输入与人物注释保持正确。
- 恢复期间移除照片、绑定期间切换项目，迟到媒体不能进入当前项目。
- 相关 Node 回归、实际浏览器、生产构建与加载检查。测试使用公开素材或合成内容，不调用真实模型。
