# CHROMA 前端重构方案

日期：2026-10-13。状态：用户确认后已实施，已完成本次前端软件验收；真实艺术效果矩阵与相机实机验收继续待办。

## 一、已确认的方向

用户访谈已确定四项：

1. 面向新手的创作引导，围绕一次完整创作组织页面。
2. 明亮、克制的影像工作室；排版整齐、留白充分、层次清晰。
3. 分步骤向导，而非所有工具常驻的单页工作台。
4. 统一落地页、登录／注册、创作页、我的 LUT 和相关对话框。

设计目标：用户能回答“现在在哪一步、正在处理哪张照片、接下来做什么、结果存在哪里”。

## 二、信息架构

顶级导航为“首页／创作／我的 LUT”，首页主要入口为“开始创作”。创作内部使用四步：选照片 → 定风格 → 调效果 → 保存作品。

项目切换与管理属于创作上下文，使用项目名＋菜单。对话历史、命名版本和图像检查进入对应步骤内的辅助入口。项目草稿状态、撤销／重做及正在进行的作业在创作期间保持可达。

“生成”在新界面中改为“创作”：它既包含 AI 生成，也包含手动、参考匹配与已有 LUT 试套，更容易理解。

### 步骤 1：选照片

主目标：建立可靠的创作起点。

- 新项目默认突出上传，说明照片用途及支持格式。
- 上传后显示足够大的照片和文件名，第一张的 AI 主样张身份明确可见。
- 拍摄输入基准用容易理解的说明辅助确认；无法仅凭 EXIF 判断 Photo Style，不能假装自动确认。
- 支持 1–5 张照片；第一次使用不要求用户先理解“验证图”。追加照片入口解释为“用其他照片检查同一效果”。
- 当前查看与 AI 主样张分别标识，更换缩略图不隐式更改 AI 输入。
- 照片详情按需展示：元数据、重绑、输入、内容识别、缓存设置、移除与相机指南。
- 保留无照片创作 LUT 的次级路径，使用明确的合成示意图；仅限制依赖真实照片的动作。
- 主操作：“继续：定风格”。返回已有项目时按实际恢复情况就地提示重绑，不要求全部从第一步重做。

### 步骤 2：定风格

主目标：把用户的视觉想法转成可判断的效果。

- 照片在左，当前创作方式和要求在右。默认保留氛围，避免误改夕阳暖调等合理特征。
- 方式为照片优化、文字调整、参考匹配；预设及已保存作品作为可选起点。
- 每种方式有一个输入区域和一个明确的执行动作；保持各方式草稿和候选。
- 当前 AI 主样张、图像分析开关、人物保护摘要靠近执行动作。人物识别或区域修正只用于全局调色的质量判断。
- 报告先显示“已应用／待应用／未应用／无变化／部分完成”等真实状态，再展开细节；不把作业完成等同于效果满意。
- 参考候选继续明确确认后应用；照片优化和文字调整保留各自现有应用契约。
- 作业运行时在步骤区显示进度、取消和恢复入口；切换页面展示不取消或重复应用作业。
- 用户可以直接进入手调，不要求 AI 必须生成过有效参数。
- 主操作依阶段变化：“分析并应用／生成候选”等，结果可用后为“继续：调效果”。

### 步骤 3：调效果

主目标：判断效果并精细调整。

- 大照片与少量基础参数优先出现；默认滑动对比，支持并排和放大查看。
- 基础参数突出曝光、冷暖、影调和饱和度，名称旁保留用途说明及参数保护。
- 高级工具按需打开：四通道自由曲线、局部色彩、分离色调、RGB、外部 LUT 和输入技术设置。
- 主／R／G／B 曲线各自独立展示；打开曲线时使用能容纳完整内容的编辑区域，避免挤压照片和堆出多个嵌套滚动。
- 放大视图继续支持同步调参；普通和放大入口共用正式参数与保护逻辑。
- 命名版本与固定 A/B 放在“比较与版本”；恢复快照有明确动作，A/B 不是实时草稿。
- 图像检查与多样张验证按需查看；统计风险不表述为艺术效果认证。
- 可以返回第二步修改风格，手调结果作为后续增量的上下文，不静默复位。
- 主操作：“继续：保存作品”。

### 步骤 4：保存作品

主目标：让用户清楚交付对象与去向。

- 展示最终预览、作品名和使用目的。
- 默认主操作为“保存到我的 LUT”；清楚区分完整效果和可复用风格。
- 完整效果包含当前单张校正；可复用风格只保存可复用贡献及必要依赖，用通俗说明表达区别。
- 照片导出作为明确的次级操作，支持 JPEG／PNG 和原尺寸；缺原文件时就地提供绑定入口。
- `.cube` 下载按相机和后期软件用途选择，保留现有命名、输入基准与使用说明。
- 分别展示“已保存到账号”“已下载到电脑”等成功结果，草稿保存不代表作品已保存。
- 返回修改后已保存资产保持独立快照，下一次保存走明确的新作品／更新修订规则。

## 三、视觉系统

### 表面与色彩

浅色是首版验收基准：近白页面背景、白色编辑表面、深灰主文字和清晰的灰色辅助文字。沿用 CHROMA 暖金色，但降低使用面积；主要用于当前主要执行动作、当前步骤和少量选中状态。

保留现有深色、中性灰主题，复用同一结构与语义变量。照片画布维持中性色，避免主题变化影响用户对照片的判断。

### 排版与间距

- 使用现有中文适配字体体系，保持统一字重、行高与数字对齐；不为每个区块换字体。
- 页面标题约24–32px，区块标题16–20px，正文14–16px，辅助说明12–13px；关键说明不靠过小字号降级。
- 间距使用4／8／12／16／24／32／48px等级：控件内8–12，同组12–16，区块24–32。48仅用于页面级章节，不给每块卡片都加大留白。
- 桌面照片约占内容宽度的三分之二，工具区约三分之一；以实际照片比例和可操作尺寸为准。
- 主要输入与按钮统一高度；图标和文字中心对齐。较长文字允许合理换行或单行截断，不压缩按钮。

### 层次与操作

- 每个步骤保留一个当前主要执行动作。
- 次要操作使用低强调描边，说明／返回／历史使用文字或图标。
- 持续状态以文字和符号表达；保护状态有未保护／部分保护／已保护三态。
- 优先用对齐、文字层级和留白分组。只有确实独立的交互区域使用面板，不把每一小段都装进卡片。
- 阴影主要用于浮层；普通内容少用厚阴影、大圆角、彩色背景和装饰渐变。

## 四、其他页面

### 落地页

- 首屏：一句明确价值表达、一张真实效果对比、一个“开始创作”按钮。
- 紧接四步创作流程，再说明 AI／手调、LUT／照片两种结果。
- 相机兼容与输入限制在相机指南中清楚表达；避免混入首屏主文案。
- 移动端保持完整照片和明显入口，不使用重复功能卡片或无依据评价数字。

### 登录与注册

- 简洁表单，明确当前是在登录还是注册，复用统一字段、错误、加载与主要按钮。
- 用户从创作入口来时，登录成功后返回原目标；认证错误不丢失无敏感信息的表单状态。
- 不在登录页重复整套营销内容。

### 我的 LUT

- 标题、简明搜索／筛选、作品列表；缩略图、作品名和用途优先。
- 项目草稿与已保存作品保持对象区别；“继续创作”应明确新建或载入目标项目。
- 作品详情承载输入条件、类型、修订与使用说明。常驻主要动作聚焦试用或打开作品，下载和管理作为次级入口。
- 删除放在管理菜单并确认，说明删除范围；不把作品删除暗示为原照片或项目删除。
- 空状态引导首次创作，加载／错误／无搜索结果分别表达。

### 对话框

统一标题、说明、字段、错误及底部操作。取消为低强调，执行为主色；危险最终确认为危险色。参数保护、候选确认、作业运行、保存未完成等状态都使用真实可用条件。

## 五、向导的导航与恢复规则

- 步骤是一种查看状态，不是新建的业务对象。切步骤不生成第二份参数，也不进入调色撤销栈。
- 已访问步骤可返回；允许跳过 AI 进入手调。技术条件限制具体动作，不用笼统锁死整个项目。
- 输入改变可能使当前比较、候选和报告过期；就地提示其真实状态，不能仅因“第二步完成”而认定当前结果有效。
- 在AI任务运行期间可查看已安全可看的内容；相关编辑仍遵守冻结和身份约束。若操作会改变任务来源，继续沿用取消或确认流程。
- 切步前提交或取消正在进行的手势与数值编辑，保持一次连续拖动可以一次撤销。
- 原尺寸导出要求File；兼容缩小缓存允许已有预览、手调及LUT保存。提示“这项操作需重新绑定”，而非“全部进度丢失”。
- 刷新先恢复账号、项目、草稿和作业，再恢复可用步骤。恢复偏好不能绕过输入确认、删除标记或过期候选检查。

## 六、前端架构安排

继续使用现有 React 18、Vite、JavaScript/JSX、普通CSS和Radix。此次重构不需要整套替换组件库。

页面职责拆分：

```text
App / StudioShell
  ├─ LandingPage
  ├─ AuthPage
  ├─ CreationFlow
  │    ├─ ProjectBar / StepNavigation
  │    ├─ PhotoStep
  │    ├─ StyleStep
  │    ├─ AdjustmentStep
  │    ├─ DeliveryStep
  │    └─ FlowActions / RecoveryNotices
  └─ LibraryPage
```

- `useWorkspace`继续是正式项目、参数、历史和保护状态的唯一来源。
- 页面编排层建立`useCreationFlow`，只负责当前步骤、访问状态及动作所需条件；步骤偏好可兼容扩展到项目`view_state`。
- AI作业、刷新恢复和幂等回执控制需要在步骤外持续运行。先将目前`AutoRetouchBar`里的业务控制抽到独立hook，再让步骤组件消费状态，避免切步卸载控制器。
- 预览和图片资源管理保持独立生命周期；按需挂载可见渲染，不为步骤复制Canvas和File。工作台首次进入后保留其业务控制和照片状态，切换到首页或我的 LUT 不卸载正在运行的 AI 控制器。
- 把既有曲线、参数、样张、版本、导出等组件组合到步骤中，逐步减少`GenerateView`承担的职责。
- 使用统一的组件变体和语义主题变量。Radix继续负责菜单、对话框、选择器、提示、键盘与焦点。
- 保留首页与工作台的加载边界，曲线／参考匹配／放大／照片导出打开时加载。
- 后端API、参数数学、照片规范化和色彩链路保持现有契约；设计阶段不引入新的调色能力。

## 七、实施顺序

1. **确认设计草案。** 检查四步流程和关键状态，对桌面／手机及浅色方向达成一致。
2. **统一视觉基础与Shell。** 建立页面宽度、字号、间距、操作层级、字段和浮层约定；实现落地页和认证入口。
3. **拆分状态编排并实现向导。** 先保证AI控制、草稿和当前参数可跨步骤持续，之后组合照片与风格步骤。
4. **实现调整与交付。** 接入四曲线、放大调参、版本、保护、诊断、LUT与照片输出。
5. **统一作品库与相关对话框。** 完成作品列表、详情、使用与管理流程。
6. **完整验收。** 检查三主题、桌面／390px、键盘、长名称、加载／空／错误、重绑、刷新恢复、跨步骤候选、撤销与导出一致性。

每阶段完成可演示结果后评审，避免把全部改动一次堆进尚未验证的新结构。

## 八、验收标准

- 首次进入用户能找到当前步骤和唯一的主要操作。
- 不滚过技术详情即可完成四步基础流程。
- 照片和参数可读；曲线展开和放大调参有足够空间。
- 主文字及启用按钮与实际背景对比度至少4.5:1；组件组合、悬停及所有主题均需真实渲染检查。
- 390px无横向溢出、控件重叠、正文裁切或底部操作遮挡。
- 原有关键能力有明确入口，功能不能因隐藏而变成不可发现。
- 项目、当前样张、AI主样张、输入确认、参数保护、候选与作业身份不丢失。
- 草稿、版本、账号作品和电脑下载的成功信息互不混淆。
- 软件验收默认使用公开或合成素材与服务桩；真实模型与用户照片按实际授权。
- 真实艺术效果矩阵与相机实机验收继续待办。

## 九、实际实现与验收

### 实现入口

- `GenerateView.jsx` 编排四步流程；`CreationNavigation.jsx` 提供步骤、标题和导航焦点；`CreationPhotoSetup.jsx` 处理上传、输入确认、重新绑定及无照片创作路径；`CreationDelivery.jsx` 聚合账号作品保存、照片导出和 `.cube` 下载。
- `useCreationFlow.js` 与 `lib/creationFlow.js` 仅管理查看步骤，写入兼容的 `view_state.creation_step`。旧项目按样张、报告和工具状态迁移；恢复完成后不因新增照片或报告自动跳步。步骤切换先结束正在编辑的参数事务。
- `useAutoRetouchController.js` 承接原 `AutoRetouchBar` 的冻结请求、作业回执、轮询、取消、续跑和幂等应用。步骤隐藏与首页／作品库切换不卸载已进入的创作控制器；真正卸载时释放界面忙状态并保留恢复回执。异步结果在等待存储后再次核对账号、项目和恢复状态。
- 基础调整先显示曝光、冷暖、对比度与饱和度，完整工具按需展开；保护状态使用明确文字和颜色。曲线继续分主／R／G／B 四通道展示，放大调参沿用同一正式状态。
- 版本 A/B 是固定快照，仅在调整步骤展示；其他步骤展示当前效果，避免保存时把历史比较当成最终结果。返回调整步骤保留比较选择。
- `StyleSaveDialog.jsx` 支持在第四步直接保存；提交期间禁止重复执行和来源变更。保存请求冻结来源，迟到结果不写入其他项目或账号。账号保存、浏览器下载、本机草稿各自表达状态。
- `LandingView.jsx`、`AuthView.jsx`、`StudioView.jsx` 与 `LibraryView.jsx` 使用相同字体、语义主题和操作层级。作品库将修订、编辑及删除收至管理菜单，提供真实加载、错误重试与空状态。搜索值不变时不触发额外请求，首次失败不会被搜索初始化隐式重试。

## 十、功能级面板修订

用户反馈初版去掉过多容器边缘，项目、导航与预览控制像散落在页面背景上的文字。此次修订按功能归属建立面板：

- 项目工具栏使用统一表面和细边框；选择器恢复可见轮廓，历史与草稿／撤销状态分组。手机将项目与状态工具分成两行，长名称保留省略。
- 四步导航置于一个独立面板，当前步骤使用淡暖色表面和边缘标记，其余步骤保持低强调。标题与章节说明在面板外保留留白；导航只表达查看位置，不宣称质量验收或业务完成。
- 照片预览面板包含展示方式、照片名、放大／曲线入口、输入说明、绑定反馈和照片舞台。控制区与画布以细线分隔；画布继续使用固定中性背景。
- 右侧工具面板与预览采用相同的外边框、圆角和内边距。曲线、样张和诊断在预览面板外保留各自空间，外层不裁切内容或键盘焦点。
- 普通状态反馈缩小内边距和视觉面积，保留真实内容与 status／alert 语义。功能面板内部使用分隔线和排版，不给每行文字加卡片或阴影。
- 使用现有语义主题变量，保持三主题可读；保留 390px 单列、四步导航和 720px A/B 自动高度规则。

验证结果：`npm test` 294 项通过，`npm run build`、`npm run check:loading` 和 `git diff --check` 通过。浏览器使用公开样张／桩接口，检查三主题、桌面／390px、长项目名、键盘切步与焦点恢复、展开曲线，以及 720px／390px 的版本比较。

## 十一、版本比较的退出与预览对象

版本 A/B 是固定快照，原图 / 当前效果是实时编辑预览。两种比较对象应有明确、常驻的切换入口，不能让「展示形式」承担隐含的退出行为。

- 在「调效果」照片面板顶部提供「原图 / 当前效果」「版本 A / B」两项选择，显示当前选中状态。当前效果下才显示「滑动对比 / 独立展示」；版本比较保留现有 A/B 预览与参数差异，避免展示形式与实际画面不符。
- 选择 A 或 B 进入版本比较。未选齐、输入不兼容、照片需重新绑定时仍可直接切回当前效果。
- 返回当前效果保留 A/B 快照，重新选择版本比较可继续查看；只有再次选择版本或更新草稿快照才更新该侧的快照。
- 进入手动调整、打开曲线、成功恢复版本到草稿时回到当前效果。查看版本管理本身不会强制覆盖当前预览对象。
- 版本面板把「返回当前编辑」改为「返回原图 / 当前效果」；放大视图顶部提供同样明确的返回入口，无需先展开调色面板。
- 本机 `view_state.comparison_mode` 记录 `current` 或 `versions`，A/B 快照仍存于兼容的 `comparison` 字段。旧草稿按是否存在比较快照恢复；明确选择当前效果后刷新仍保持当前效果。
- 切换比较对象不恢复版本、不修改正式参数、保护项、照片或编辑历史。版本恢复继续走原有事务与输入确认；账号和项目隔离不变。

回归验证覆盖选两版后进入手动调整、直接退出及再次进入、部分选择退出、旧草稿恢复和明确退出后的刷新；浏览器检查桌面、390px、三主题、键盘以及放大视图退出。

实施验证：新增 5 项实际生成页状态回归，全部前端测试 299 项通过；生产构建、加载预算和补丁空白检查通过。浏览器使用公开样张和本地接口桩，检查选择两版后进入手动调整、普通滑动／独立展示恢复、A/B 保留与重新进入、放大视图直接退出且窗口保持打开、退出后刷新、键盘切换，以及 390px 和三种主题。窄屏放大查看标题与返回按钮分行，避免标题被挤压。未调用模型或写入真实账号及后端数据库。
