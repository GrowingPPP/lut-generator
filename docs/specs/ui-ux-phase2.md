# CHROMA 第二批 UI 优化方案

日期：2026-10-13。状态：UI2-01 至 UI2-04 已实施，软件检查及三种主题的桌面、移动浏览器验收已完成。真实艺术效果矩阵与相机实机验收继续待办。

## 1. 目标与依据

沿用已确认的“明亮、克制、以照片为中心”方向：排版整齐、留白充分、层次清晰。第二批将第一批的工作台体验扩展到通知、表单、对话框及落地页。

依据为[前端审核方案](ui-ux-pro-max-audit-2026-10-13.md)第 8 节的第二批范围：UX-07／10（视觉规格、通知、字段、对话框）及 UX-09（落地页叙事）。参考[四步创作方案](guided-creation-redesign.md)、[操作层级](action-hierarchy.md)与[参数入口修订](manual-parameter-discoverability.md)。

本次继续使用 ui-ux-pro-max。局部检索 `error recovery feedback` 匹配到错误恢复、就地反馈及错误朗读规则；`product demo storytelling` 匹配到产品演示与功能说明的叙事结构。采用适用的恢复动作、明确说明和连续演示原则，沿用本项目琥珀色与既有字体、Radix 组件。

## 3. 任务与实施顺序

### UI2-01：统一视觉规格

先为后续改动建立有限的共用规则：

- 间距使用 4／8／12／16／24／32／48／64px。面板内部通常 16–24px；同组字段间距 12–16px；关联区域间距 24–32px。
- 表单与任务标题 16–18px，常规标签和说明 14px，辅助元数据 12–13px。主要页面正文以 16px 为参考；触控输入使用 16px 避免浏览器自动放大。
- 常规桌面控件高 40px；窄屏和触控的常用按钮、图标及字段目标高至少 44px。紧凑外观通过图形大小表达，有效点击范围保持足够。
- 页面的宽度按用途保留差异，统一导航与内容的边距及对齐规则。工作台保留照片宽度；落地页和作品库用适合阅读的内容上限。
- 功能面板统一细边框、8–12px 圆角和语义表面；内部靠栅格和轻分隔组织，减少没有独立交互目的的嵌套框。
- 主操作、次操作、轻操作及危险确认沿用现有按钮层级。前景、背景、边框作为组合一起检查，包含主题切换、悬停、焦点和禁用。

优先在主题与共用控件样式集中规则，清理受影响的重复覆盖；按页面迁移，避免全局一条选择器同时改坏照片工具和营销入口。不引入整套新的 UI 库或在线字体。

### UI2-02：统一通知、状态与恢复

| 情况 | 展示与生命周期 | 恢复方式 |
|---|---|---|
| 已执行成功 | 简短、低打扰提示；普通成功可短时消失，悬停／聚焦暂停计时，保留关闭入口 | 保存后作品身份及下载记录仍可在所属区域查看 |
| 必须处理的条件 | 就地常驻，例如输入未确认、原文件缺失、外部 LUT 资源丢失 | 明确的确认输入、重新绑定或载入资源入口 |
| 作业运行／排队 | 在所属任务面板持久展示实际阶段；切到别处后提供返回入口 | 查看进度与取消，保留原作业身份 |
| 失败 | 靠近失败的操作，说明原因和下一步；不自动消失 | 使用既有重试、保存重试、重新绑定或修改条件动作 |
| 部分完成／无变化／未应用 | 保留真实结果摘要，明确哪些变化实际生效 | 查看报告、继续调整或用户明确发起的新操作 |
| 保存冲突／同步异常 | 放在项目或草稿状态附近，区别本机保存与账号同步 | 沿用已有冲突处理、重试和备份动作 |

实施要点：

- 新增或复用轻量通知展示与错误说明模块，显式携带类型、所属区域、文案和可用动作。类型由发起操作提供，不依赖匹配中文文案猜测成功或失败。
- 数据身份与现有异步边界保持一致。项目切换后不展示旧项目的短提示；当前任务持续状态从已有作业控制器派生，不能因通知关闭丢失恢复入口。
- 成功使用温和朗读，重要失败使用 alert；避免同一事件在多个区域重复朗读，也不把每个百分比变化都设为打断朗读。
- 具体可理解的业务原因继续显示；网络、认证和契约异常给普通语言摘要。需要诊断时提供展开详情，不直接把大段异常栈或 JSON 放在页面主提示中。
- 诊断详情不包含密码、令牌或照片内容。保留 API 的状态码、业务 code 和 accepted 等供现有逻辑判断，不能把“服务可能已接受请求”误当成可以重新发起的失败。
- 错误恢复调用既有处理器。不会为了显示重试按钮自动重发 AI、作品保存、删除或照片上传。

先迁移工作台主要路径，再对齐作品库、保存与导出反馈。现有样张绑定阶段和作品库加载状态保留真实语义。

### UI2-03：统一表单与对话框

覆盖作品保存、照片导出、项目管理／命名、删除确认、参考匹配候选，以及登录与作品编辑中的共用字段展示。

统一结构为：标题与简短说明 → 字段／内容 → 就地错误 → 底部动作。

- 一个对话框保留一个清楚的标题；技术说明进入帮助或详情，重要条件仍可见。
- 字段标签、辅助文字、单位、错误及输入边线一致。具体字段校验关联对应输入；无法归因到单字段的服务错误放在表单区域，避免错误地指向密码等字段。
- 取消为低强调，当前执行为主色，危险最终确认为危险色。保留忙碌禁用、防重复提交和现有取消语义。
- 桌面按内容使用合适宽度；手机保留侧边距，正文可以滚动，关键动作和错误可达。高度受视口约束，不遮挡输入焦点。
- 验证 Tab 顺序、Enter 提交、Escape 关闭、焦点进入与返回原入口。嵌套帮助优先关闭自身，保留外层窗口。
- 普通确认与名称输入优先复用现有 Radix Dialog；照片放大保持其专用布局，只对齐共用字段和通知规格。

不修改候选应用、项目删除、原照片保留、保存类型或导出色彩的业务契约。

### UI2-04：落地页形成完整创作叙事

顺序保持清楚且与工作台一致：

1. **首屏**：当前价值表达、真实照片比较及“开始创作”；补充入口保持低强调。
2. **四步流程**：选照片、定风格、调效果、保存作品，文字简短，与工作台名称一致。
3. **重点案例**：同一张公开照片、一个明确想法、预先确定的参数摘要及引擎渲染结果。把描述和效果放在同一段，让用户看懂输入、调整和产出。
4. **两个辅助能力**：精细调整与参数说明；保存／导出／复用。每块保留一项重点，不再各自复制完整流程。
5. **相机与后期**：清楚的输入和使用条件。
6. **FAQ 与结束入口**：简短回应主要疑问，进入创作。

案例不是现场模型调用：语言与参数示例明确标记为预设示例，照片使用当前引擎渲染，不能把预设参数冒称为实时 AI 结果。真实功能入口仍进入创作工作台。

桌面让案例照片成为主视觉，说明作为伴随内容；窄屏先交代想法，再展示完整照片与简短摘要。减少四个等权重大块的重复文字，使用对齐和章节间距建立节奏。支持现有比较键盘交互、减少动态效果偏好及图片失败回退。

本批维持已有加载预算，不添加视频、3D 演示或大依赖。以实测为依据调整演示启动时机属于第三批。

## 6. 实施结果

### 6.1 共用视觉规格

`themes.css` 集中页面宽度、侧边距、间距、控件高度与圆角变量。工作台／作品库内容上限为 1540px，落地页／登录页的阅读宽度为 1280px；导航按所在页面对齐。常规控件桌面为 40px，窄屏或触控为 44px。照片舞台继续使用固定中性背景。

基础按钮、选择框和表单字段复用这些规格；小尺寸按钮在手机保留足够点击范围。放大调色维持专用结构，同时对齐工具按钮高度。任务对话框的标题、内容滚动、字段间距和底部动作统一，手机与低高度窗口受视口约束。

### 6.2 通知与错误恢复

新增共用 [Notice](../../frontend/src/components/ui/Notice.jsx)、[通知说明](../../frontend/src/lib/notices.js)和[项目提示 hook](../../frontend/src/hooks/useOperationNotice.js)。发起操作显式提供类型与所属区域，不根据中文文案判断成功或失败。

- 普通成功提示默认 6 秒后关闭，悬停或焦点停留时暂停，离开后继续剩余时间。
- 失败、警告与运行提示常驻；AI 提示在对应创作方式附近展示，切到其他步骤后可以返回原任务。通知关闭不删除控制器的作业或恢复记录。
- 提示按账号和项目隔离；旧项目回调不能覆盖新项目提示，旧提示的关闭回调不能关闭新提示。
- 认证、网络和技术契约错误转为普通语言；中文业务原因保留。诊断区只提供 HTTP 状态、受限格式的业务 code，以及服务可能已接受请求的说明，不展示异常栈、原始 JSON 或照片输入值。
- 保存、导出、作品加载及编辑、项目管理、参考匹配使用同一错误展示。文字微调的回复和通知也使用安全摘要，避免技术异常从对话区重新暴露。
- 恢复按钮调用既有处理器；不自动重发模型请求、保存、删除或上传。草稿冲突、作业幂等和来源检查继续由原模块负责。

### 6.3 表单与对话框

作品保存和照片导出使用实际表单，支持 Enter 提交；关闭和取消明确为非提交按钮。登录缺失字段显示对应状态并聚焦首个缺失项；无法归因到具体字段的服务错误放在表单区域。项目搜索增加可见标签，项目命名校验保留字段关联。

实际验收发现，懒加载照片导出窗口关闭后焦点会回到页面正文。已从交付入口显式传入焦点引用，Escape 关闭后回到原导出按钮。共用 Radix Dialog 的忙碌关闭、嵌套浮层和危险确认语义保持原行为。

### 6.4 落地页

原来的四个等权重功能块整理为一个完整公开样张案例和两个辅助能力：精细调整／说明，以及保存／导出／复用。案例展示“留住林间的暖光”的想法、参数摘要和同一照片的前后效果，摘要与渲染取自同一预设对象。

页面明确说明这是固定配方与产品引擎渲染的示例，未实时调用 AI。保留首屏、四步流程、相机与后期条件、FAQ 和创作入口。图片加载失败时给出回退说明并禁用失效比较，仍可进入创作。

## 7. 验证与页面验收（2026-10-13）

### 7.1 环境与边界

浏览器真实运行 React、Radix、CSS 和 Canvas。使用仓库公开 `frontend/public/landing/preview.jpg`、`hero.jpg`；账号、作品、归一化、AI 作业和导出 API 用页面级桩隔离。没有创建真实后端账号、修改业务数据库、调用模型或发送私人照片。

归一化桩只验证照片选择、绑定和界面状态，导出桩只验证提交、失败、重试与焦点；本批不据此声称真实 ICC 转换或预览／导出像素一致性通过。手机验收使用浏览器视口模拟，软键盘、安全区和实体设备触摸手感仍需真实移动浏览器补充。

### 7.2 实际覆盖
