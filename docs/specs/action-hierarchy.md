# 聚焦操作与保护状态

## 目标

生成页、放大调色视图及相关对话框采用一致的操作层级。用户能识别当前关键动作、持续保护状态和低频管理入口。

## 交互规则

- 实心主色用于当前主要执行动作和保存结果；浅色强调用于相关的次要操作；描边用于普通次要操作；文字与图标入口用于辅助操作。
- 危险操作集中在管理菜单，与普通项分隔；最终确认有明确动作名称。关闭、取消与说明入口保持低强调。
- 样张缺原文件时突出绑定，输入待确认时突出确认，输入兼容后显示可用状态。设为 AI 主样张保持显式操作；已是主样张时显示状态，避免重复禁用按钮。重新绑定与移除进入样张管理菜单，移除确认明确保留原照片和 LUT。
- 每个参数及参数组使用一致的锁定控件，包含图标、可访问名称、按下状态与说明。组的部分保护状态可见。自由曲线及外部 LUT 的保护入口贴近各自标题。
- 参数组部分保护时，点击补齐组内保护；全部保护时，点击解除组内保护。生成页和放大调色视图采用相同规则。
- 参数管理显示保护数量、全部保护／解除全部保护和复位未保护项。全部保护覆盖所有参数；复位继续排除输入基准和显示映射，并保留受保护字段。复位前说明涉及调色参数、自由曲线和外部 LUT，并允许取消。
- 保护同时限制手动与 AI 修改。锁定、复位、调参沿用现有事务、撤销和草稿保存；放大与生成页共用参数入口。
- 保持 Radix 菜单、Tooltip 与 Dialog 的键盘导航、焦点恢复、忙碌禁用和嵌套层关闭行为。菜单打开后进入忙碌状态不得执行旧操作。

## 实施范围

共用操作样式、保护状态控件；样张详情与确认；生成页参数与曲线／外部 LUT 标题；放大查看工具和调色面板；保存、导出、参考匹配、输入确认及项目／版本相关对话框。

## 验证

- 普通／全保护／部分保护及全部解除；锁定项禁用手动输入，复位保留锁和技术输入，取消不改参数。
- 样张缺文件、待确认、兼容及不兼容输入、主样张和验证图；菜单重绑保持目标，移除保留原文件与 LUT。
- 主菜单和放大视图保持相同操作范围，相关对话框只有明确的主执行按钮。
- 浅色、深色、中性灰，桌面和 390px，长名称、键盘、焦点与嵌套菜单。使用合成或公开素材及本地接口桩，避免真实模型请求。
- 相关前端回归、生产构建、加载预算与独立审查。真实艺术效果和相机实机验收继续待办。

## 首页按钮可读性回归修复（2026-10-12）

用户反馈首页按钮文字不可见后，在实际首页复现了三个主按钮白底白字、对比度 1:1 的问题。原因是 `UIFoundation.css` 新增的普通 `.btn` 背景规则在 `.btn-primary` 之后加载；首页使用合法的 `btn btn-primary` 组合，因此主色背景被普通面板背景覆盖，主按钮文字色仍为白色。此前工作台验收使用独立 `btn-primary`，没有覆盖首页组合，是验收遗漏。

修复普通按钮的底色规则，明确排除主按钮与危险按钮，并使用 `:where()` 保持低特异性，避免压过 soft／ghost 变体。禁用的主按钮保留原有主色／文字配对；LUT 卡片的普通背景及悬停规则也排除语义变体。首页按钮保留组合类。

实际登录页与工作台已检查三个主题；普通、主、辅助和危险按钮的 24 种组合每个主题均可读，最低启用状态对比度为浅色 6.09:1、深色 7.52:1、中性灰 5.66:1。浅色主按钮对比度为 6.09:1，深色为 8.37:1，中性灰为 11.32:1。前端 262 项测试、生产构建与加载检查通过。验收使用隔离账号和本地接口桩，临时项目缓存已定向清理。

新增实际浏览器回归脚本 `frontend/scripts/check_button_contrast.mjs`，检查首页三个主按钮的三主题、桌面／390px、正常／悬停状态；使用渲染后的颜色和背景计算对比度，启用按钮低于 4.5:1 时失败。需启动本地前端并安装、连接 Ego Browser：

```bash
ego-browser nodejs < frontend/scripts/check_button_contrast.mjs
```

共用按钮样式修改后须包含首页组合类及登录入口的验证，不能仅凭主题变量检查或工作台截图判断全站通过。

新增浏览器回归已执行通过：三个首页主按钮 × 三个主题 × 桌面／手机 × 正常／悬停，共 36 个状态，计入悬停透明度后的最低对比度为 4.93:1，失败项为 0。

## 调色项目顶栏整理（2026-10-13）

项目选择器上方的文字标签使其形成两层结构，而相邻历史和编辑按钮只有一层，导致实际控件不水平。顶栏改为单层项目入口：直接显示当前项目名，保留可访问名称“调色项目”，旁边的管理图标打开既有项目菜单。历史、项目、编辑及交付操作使用统一的 40px 控件高度和垂直中心线。长项目名截断显示，完整名称通过现有标题提示及选择菜单查看。

桌面保持一条水平操作线；空间不足时按项目区与编辑区分行。390px 下第一行保留对话历史、项目选择和管理入口，第二行容纳撤销／重做／新建，保存状态用低强调文字独立显示，保存／导出保持底部操作区。草稿保存错误及修订冲突独立展示在顶栏下方，不改变项目控件的对齐。

沿用项目切换、历史、管理、编辑及交付回调，不改变草稿格式和项目身份。验收覆盖三个主题、长名称、桌面与390px、选择器与管理菜单的键盘／焦点、保存错误与冲突布局，执行生产构建和加载检查。

实际长名称验收发现 `Select.Value` 会忽略 `className`，原有省略样式未落到 DOM。共用选择器增加真实的 `.select-value` 包装，保留完整名称和标题提示，长名称只做单行视觉截断；选择值、表单和键盘逻辑保持不变。

已完成验收：前端 268 项测试通过（新增 6 项保存恢复入口回归），生产构建、加载检查及 `git diff --check` 通过。三个主题各检查 11 种窗口尺寸，包括390px、560／561px、960／961px、1180px、桌面与宽而矮窗口，共33组；项目区域中心对齐，选择器保持40px，无横向溢出或按钮重叠。项目切换与重命名正常，选择器、管理菜单与对话历史按Esc关闭后焦点回到原入口。模拟实际本机保存失败及BroadcastChannel修订冲突，提示位于顶栏下方，长无空格错误可换行；保存重试仍可成功执行。

浏览器使用独立临时账号、合成示意图和本地API桩，没有真实模型调用或用户照片。验收后的临时页面及该账号的本机草稿均定向清理。
