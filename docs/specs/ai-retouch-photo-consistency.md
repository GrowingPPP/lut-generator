## 一致性核对方法

冻结应用后的参数、来源摘要与主样张身份。切换到独立展示，读取右侧 WebGL canvas 的原生 2048 × 2048 PNG，并保存左侧规范化原图。通过页面下载同一快照的 4000 × 4000 PNG 与 JPEG（质量 95）。滑动对比另确认右侧已实际渲染，没有黑图。

数值参考使用同一冻结参数在前端生成的真实 33³ Float32 LUT 网格，转换存储轴次序后在 CPU 采样。浏览器预览与原尺寸 PNG 分别比较同尺寸输入，避免把两个分辨率直接设成零误差门槛。JPEG 则与同一下载 PNG 按相同质量、采样及优化设置重新编码后的解码像素比较。

所有比较均检查实际来源 SHA-256、主样张身份、正式作业成功与应用状态、参数一致性、图像尺寸以及非空渲染。原尺寸参考按块处理。

## 数值结果

“编码值”指 8 位 RGB 的 0–255 数值；平均差与最大差均为 RGB 通道绝对差。

| 核对 | 平均绝对差 | 99% 通道差不超过 | 最大差 | 结论 |
|---|---:|---:|---:|---|
| 浏览器规范化原图与后端同尺寸原图 | 0 | 0 | 0 | 输入像素完全一致 |
| 实际 WebGL 预览与同尺寸前端 LUT 参考 | 0.007679 | 0 | 1 | GPU 运算及最终量化允许的差异 |
| 实际原尺寸 PNG 与前端 LUT 全尺寸参考 | 0.000001604 | 0 | 1 | 99.9998396% 通道完全相同，前后端浮点精度一致 |
| 实际 JPEG 与同一 PNG 的相同 JPEG 编码参考 | 0 | 0 | 0 | 解码像素完全一致，未导出另一套效果 |
| 原尺寸 PNG 缩小后与实际预览 | 0.031391 | 1 | 8 | 不同处理顺序下视觉核对通过，不声称逐像素相同 |
| 实际 JPEG 与无损 PNG | 0.847927 | 3 | 18 | JPEG 压缩带来的实际差异，单独记录 |

前后端 LUT 的最大浮点差为 `2.9792785682936085e-08`。实际预览相对原图的平均变化为 1.081742 个编码值、最大 8，证明比较对象包含已应用的轻微饱和度调整。WebGL 支持 `OES_texture_float_linear`，`gl.getError()` 为 0，上下文未丢失。

PNG 和 JPEG 均保持 4000 × 4000，包含 sRGB ICC，不含来源 EXIF。预览先缩小再调色，原尺寸导出先调色；非线性 LUT 与缩放不交换顺序，所以缩小导出文件与预览之间允许少量差异。结论限定为本照片、STD 输入、实际应用的轻微饱和度调整，不扩展为所有参数、输入和设备的穷尽验证。

## 自动修图质量问题

### 非人物暖色区域触发肤色保护

本照片只有树皮与嫩芽，没有人物。当前肤色保护使用 YCbCr 等颜色条件，没有人脸或人物区域检测。首次作业的 512 × 512 统计中，颜色掩膜命中 204,573 / 262,144 个像素，即 78.0384%。暖棕树皮和背景也被纳入了这一范围。

首次两轮候选的色相／饱和度偏移分别为 0.0604146、0.0523902，高于当前 0.045 阈值，因此拒绝计算符合现有规则；问题在于将颜色启发式表述和使用为确定的肤色证据。这会限制非人物场景的自动校色。第二次作业同样发生基础校正被拒绝，不能把目标 partially_met 表述为全部修图成功。

待改进：将颜色证据明确标为疑似区域，并用人物区域证据或明确的人像上下文决定人物保护；增加树皮、暖色风景等负例。不能通过放宽所有照片的保护阈值解决这个问题。

### 零变化视觉复核仍声称改善

首次作业最终参数与初始参数相等，独立重新渲染后两图逐像素相同。视觉复核读取的是最终参数，没有误用被拒绝的候选，但模型仍声称“更暖、对比更足”，与实际像素矛盾。

待改进：没有效果变化时跳过前后改善评价并明确显示未改变；如保留当前画面评价，应向模型明确提供零变化事实，避免生成前后改善措辞。

这两项本轮作为实际验收发现记录，未调整保护规则、模型提示或复核行为。本轮没有发现预览与照片导出的调色实现不一致。

第二次作业另记录了 `review=None`、`review_skip_reason=None`，但 review 阶段为 done。当前复核函数将空内容当作没有错误的返回，因此不能将阶段完成解释为已有有效复核意见。后续应将空复核标记为未完成，并提供准确的状态与原因。
