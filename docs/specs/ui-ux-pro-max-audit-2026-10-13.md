# CHROMA 前端体验审核与优化方案

日期：2026-10-13。状态：审核与第一批实施、软件和页面验收已完成；后续批次继续待办。

审核使用 `ui-ux-pro-max`，结合源码与实际浏览器页面审查。第 1–10 节保留先出方案时的审核依据；审核阶段只新增此文档。用户随后授权第一批实施，具体决定与新验收结果见第 11–12 节。第一批提交范围包含工作台所需的四步创作流程、版本比较切换和作业控制器依赖；落地页、登录页、作品库及本机配置的其他改动不纳入本批。

## 1. 设计结论

继续采用已确认的方向：**明亮、克制、以照片为中心的创作工作台**。落实“排版整齐、留白充分、层次清晰”，需要同时考虑内容结构与操作位置。

当前四步创作流程、功能面板边界、真实照片对比和按钮层级已经提供了清楚的基础。下一轮的重点是：

1. 减少工作台顶部连续叠放的导航、标题和提示，让照片与主要操作进入首屏。
2. 用一致的栅格、文字规格和面板层级组织内容，把留白分配给照片与实际操作。
3. 统一普通调色、放大调色和移动端的基础参数、保护状态与帮助入口。
4. 落地页围绕一次真实创作展示产品价值，降低平铺功能区的重复感。
5. 补齐键盘对比、触控范围、主题切换及状态反馈等体验细节。

继续使用现有 React 18、Vite、JSX、普通 CSS 和 Radix。专业感主要来自信息组织与细节一致性；现有组件体系可以承载这些优化。

## 2. 审核方法与范围

### 2.1 Skill 的使用

- 运行设计系统查询：`photo editing creative tool`，设置 variance 3、motion 2、density 5。
- 采用查询结果中简洁栅格、清楚的操作重点、真实产品演示等原则。
- 查询返回的通用紫蓝深色配色、Poppins/Open Sans 字体不符合本项目已确认方向，继续沿用 CHROMA 的琥珀色和现有中文适配字体体系。
- 补充检索键盘操作、错误恢复、文字对比度及 React 组件组织；React 建议只采用适用于当前 React 18 的部分。
- 渐进展开检索在一次收窄重试后仍无匹配记录。相关建议来自 Skill 内置 `progressive-disclosure` 准则与实际页面观察，未将其作为数据库匹配结果。

## 3. 问题清单

P1 表示首批应解决的操作与可读性问题；P2 表示随后统一的布局与视觉问题；P3 表示可独立安排的增强项。这里没有把产品偏好包装为功能故障。

| 编号 | 优先级 | 问题及证据 | 建议 |
|---|---|---|---|
| UX-01 | P1 | 桌面工作台顶部占用过多高度。1440×900 基础手调状态中，照片舞台从约 y=586 开始；项目栏、步骤、标题说明、旧成功提示及预览工具栏连续叠放。定风格页的 AI 执行按钮落在首屏之外。 | 压缩上下文区域，将步骤说明和状态并入相应区域；照片与主要执行动作优先进入首屏。 |

| UX-07 | P2 | 通用 `status` 使用同一整行面板表达多种结果；“已确认照片输入”的成功消息跨步骤停留。API 错误仍可能带入面向开发者的细节。 | 成功用短提示，待处理条件就地常驻，作业进度持久显示；失败提供明白的原因和恢复动作。 |
| UX-08 | P2 | 功能面板边界已有改善，但组件内部仍出现多层标题、说明和分隔。四条曲线说明的换行数不同，导致图形和输入行不齐。 | 每个独立任务保留一个外层面板；内部用栅格和轻分隔。统一曲线标题、图形、坐标与操作行的基线。 |

| UX-10 | P2 | 首页、工作台、作品库分别使用约 1280／1540／1200 的内容上限，导航与内容边线缺少明确统一规则；小型帮助、照片操作等触控区域约 28–36px。 | 建立全站容器、间距、文字、字段与触控规格；页面可因用途不同拥有不同上限，但共用边距和对齐逻辑。 |
| UX-11 | P3 | `App` 用内存 `view` 切换首页与工作台，当前 URL 不表达页面。刷新后回到首页，浏览器返回不对应创作中的查看位置。 | 补充可恢复的页面／项目／步骤地址状态，认证后再恢复归属明确的项目。 |
| UX-12 | P3 | 作品库的引擎缩略图为合成示意图，其他封面为主题图形，难以单靠封面识别真实照片效果。登录缺少密码显示入口和更完整的字段错误关联。 | 先准确标记封面类型，后续提供用户明确选择的作品封面；补齐密码可见性和就地错误。 |

三种主题分别抽查了 169 个可见文字节点，在本轮可处理的纯色背景样本中未发现低于对应文字对比度目标的稳定状态。该结果不涵盖照片背景、渐变、所有透明叠加或禁用状态，不能当作完整无障碍认证。

## 4. 统一视觉系统

### 4.1 分区层级

| 层级 | 用途 | 处理方式 |
|---|---|---|
| 页面背景 | 承托整个页面 | 浅灰近白，保留安静的外围留白 |
| 功能面板 | 项目上下文、步骤、照片、当前任务 | 白色表面、清楚的细边框、约 8–12px 圆角；同级边界一致 |
| 面板内部 | 参数行、帮助、设置、元数据 | 对齐、行间距、轻分隔；有独立交互目的时再使用内嵌表面 |
| 浮层 | 菜单、对话框、帮助、移动参数面板 | 清楚的遮罩或阴影、稳定焦点与关闭入口 |

琥珀色集中表达当前主要操作和选中状态。保护、成功、警告、危险使用现有语义颜色，并配文字或图标，确保用户无需只靠颜色区分状态。照片舞台继续保持固定中性色。

### 4.2 排版和留白

- 沿用现有中文字体回退，统一字重与数字对齐；无需引入新的在线字体。
- 工作台页面语境通过项目和步骤表达，步骤说明就地呈现；大标题主要保留给营销章节、独立页面及需要建立语境的空状态。
- 面板标题约 16–18px，关键说明和参数标签约 14px，辅助元数据 12–13px；移动输入优先 16px。
- 间距集中为 4／8／12／16／24／32／48／64px：同组紧凑、任务间清楚、章节间舒展。工作台相邻功能面板约 16–24px，落地页章节桌面约 64–80px、移动约 32–48px。
- 工具区宽度约 340–360px；窄桌面依据照片可用宽度调整侧栏展示，避免只保留很窄的照片。
- 普通桌面按钮保持紧凑；触控设备的常用操作有效点击区域以至少 44×44px 为设计目标。44px 是本方案的触控舒适性目标，不能直接等同于所有无障碍规范的最低要求。

### 4.3 操作层级

- 每个任务面板突出一个当前主要动作，例如“分析并应用”或“保存到我的 LUT”。
- “继续下一步”是流程导航；需要执行创作动作时降低它的强调，避免两处主按钮竞争。
- 放大、管理、帮助、返回、重命名等使用次级或轻量样式，危险确认使用危险样式。
- 参数保护以锁状态和摘要表达。批量保护、解除、复位放在管理菜单，保留当前保护数量及部分保护状态。

## 5. 创作工作台方案

### 5.1 桌面结构

顺序调整为：

1. **项目栏**：项目名与管理、对话历史；另一侧为草稿状态、撤销和重做，所有控件中心对齐。标准状态约 48–56px 高。
2. **四步导航**：继续保留功能面板边界，约 48–56px 高；当前步骤明确。步骤解释通过当前任务面板或帮助展示。
3. **主体**：照片面板与当前任务面板顶部对齐。预览头部只放比较对象、展示方式、当前照片与放大入口；输入条件用紧凑状态和详情入口表达。
4. **辅助信息**：样张条紧邻照片；照片详情、图像检查、完整报告、技术设置按需展开。

正常已确认照片状态下，1440×900 的照片舞台顶部目标不超过约 280px，主要任务动作在首屏可见。这是下一轮的验收目标，当前尚未达到。输入未确认、保存冲突等必须处理的问题允许占用明确的提示区。

照片区域在长参数调整时保持可见，控制一个清楚的主要滚动区域。工具面板的固定动作区与内容滚动边界需要一起设计，避免增加多层嵌套滚动。

### 5.2 定风格

默认信息顺序：

1. 创作方式：照片优化／文字调整／参考匹配。
2. 当前目标的简明摘要及输入。
3. 主动作：分析并应用、提交文字调整或生成参考候选。
4. 动作附近展示 AI 主样张、图像分析开关、照片发送用途及人物保护摘要。
5. 目标详细说明、区域人工修正和技术设置按需展开。
6. 结果先展示真实应用状态和主要变化，再展开过程与其余参数。

高级说明展开后仍能找到执行入口。人物定位仅服务质量检查，不把它描述为局部肤色调色能力。作业运行、取消、部分完成、无变化、待确认等状态保持现有真实语义。

### 5.3 调效果与放大调色

- 两处共用基础参数顺序：曝光、冷暖、对比度、饱和度。
- 使用一致的“基础／全部参数”入口和展示偏好。切换视图只改变展示，不产生第二份正式参数。
- 保护摘要与管理合并成紧凑标题行；帮助保留在名称旁。新手指南作为可发现的帮助入口，不持续占据第一项滑杆前的大块空间。
- 参数值和单位对齐，保护按钮有效点击范围足够；分组标题和复位保持轻量。
- 曲线保留主／R／G／B 独立展示：宽屏四列、中屏两列，窄屏保留各通道的清楚入口和独立图形。统一标题区高度、图形坐标与操作行；合并重复的曲线大标题和帮助说明。
- 普通对比与放大对比明确显示“原图／当前效果”或“版本 A／B”。继续保留已修复的退出版本比较入口，避免查看状态被误解为恢复参数。

### 5.4 移动端聚焦布局

- 合并冗长上下文：紧凑全站导航、项目摘要和四步导航。
- 照片按内容比例显示，允许扩大查看；减少固定高度造成的无效黑边。
- 手调使用照片下方的可调高度参数面板：收起、基础、展开。基础状态直接显示滑杆，调整时照片仍保持可见。
- 当前任务主动作靠近操作区或固定底部，适配安全区域和软键盘；不遮挡错误、输入、参数和取消入口。
- 元数据、全局管理和帮助进入可发现的菜单或展开区；不把桌面全套工具先后排成一条长页面。

390×844 的普通已确认照片状态下，主要照片与当前操作入口应在首屏可达；不应要求滚动到 y≈1694 才能执行 AI 操作。

### 5.5 步骤和通知

- 步骤表达当前位置，并可补充“照片待确认／已确认”“作品已保存”等客观状态。
- 不用四步进度判断用户是否已经获得满意的艺术效果。允许跳过 AI、返回修改和按实际条件恢复。
- 短成功提示就地或短时显示；需要用户处理的条件保持显示；作业状态有固定恢复和取消入口。
- 失败信息使用普通语言、关联到对应区域，并提供重试、重新绑定或修改条件。诊断详情放在展开区，便于复制。

## 6. 落地页与全站方案

### 6.1 落地页

保留首屏清楚的标题、真实照片前后对比及“开始创作”。首屏已具备可读性和明确入口，优先改善下方叙事。

建议结构：

1. **首屏价值**：一句核心表达、真实效果、一个主要入口。
2. **四步流程**：与工作台一致，简明说明一次创作的路径。
3. **一个重点演示**：从一句描述到照片变化，连贯展示表达、可理解的调整摘要和最终效果。
4. **两个辅助能力**：精细调整；保存、照片导出与 LUT 复用。图形与文案遵循统一基线，降低重复解释。
5. **相机与后期使用**：准确说明输入、使用对象和兼容条件。
6. **简短 FAQ 与结束入口**。

演示应使用当前产品能力与公开素材，区分真实效果与界面示意。不增加无依据的评价、用户数或兼容承诺。窄屏减少等权重的大块功能展示，保留完整照片和自然章节节奏。

### 6.2 我的 LUT、登录与对话框

- 作品库保留现有搜索、类型和管理能力；统一卡片图像比例、标题、说明、标签与操作基线。合成预览和图形封面应表达其真实用途。
- 如果增加个人照片封面，需用户明确选择，并设计缩小副本的保存与移除规则，不能自动上传原照片。
- 登录／注册统一字段高度、标签、错误、加载与返回目标；增加密码显示入口，错误关联到对应字段。
- 保存、导出、项目管理、参考候选、删除确认共用标题、字段、错误与底部操作区的规格。保留危险操作范围和现有确认契约。
- 全站采用共同的导航边距及容器规则，营销页和编辑页可分别使用适合自身内容的宽度。

### 6.3 后续增强

- 地址或 hash 表达首页、创作、作品库及可恢复的项目／步骤位置。认证和项目归属核实后再恢复，失效或已删除项目给出安全回退。URL 不包含照片、令牌或模型提示词。
