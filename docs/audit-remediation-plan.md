# 全面审核后的修复计划

按用户可感知的结果拆分任务。每项完成后以自动测试或可复现的页面流程验收。

| 批次 | 问题 | 修复任务 | 验收标准 |
| --- | --- | --- | --- |
| 1 | 预设、基准切换后下载旧 LUT；页面切换丢草稿 | 下载始终按当前参数生成；生成页保留挂载；清理会话切换时的临时状态 | 切换预设、基准、页面后，参数、预览、导出一致 |
| 2 | 自动修图忽略当前调色；风格绝对值被当增量；越界提议绕过 R6 | 以当前渲染结果诊断；转换风格参数语义；校验原始候选；保守解按本次增量限幅 | 非默认参数、风格 RGB、越界提议有回归测试 |
| 3 | 自动报告刷新后不能撤销，保存失败却报告成功 | 持久化修图前参数与撤销动作；响应带会话 ID；落库错误显式返回 | 刷新、重开后能看到真实调整并撤销；落库失败不显示成功 |
| 4 | 大图和同步计算阻塞服务；配额跨进程失效；认证暴露令牌 | 同步接口由线程池执行；上传限流读取、图片降采样；数据库原子预留配额；只用安全 Cookie；限制文本长度 | 大图、并发配额、认证边界测试通过 |
| 5 | 相机 LUT 输入风格与文件名易错；删除误操作；隐私信息不明显 | 在界面明确匹配 Photo Style、一次性样张限制、视觉复核数据用途；机内文件名使用兼容 ASCII；删除前确认 | 用户可在下载前理解兼容条件与样张适用性 |
| 6 | 文档和回归覆盖落后 | 更新使用与设计文档；运行后端、前端、构建和 LUT 对齐验证；页面复测 | 全部检查通过，问题可按上述场景复核 |

实施时优先保证既有 API 的图片不落库约束。自动修图结果只保存参数和摘要。工作在 `codex/audit-fixes` 分支进行。
